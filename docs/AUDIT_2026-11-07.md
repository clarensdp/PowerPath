# PowerPath — full technical and UX/UI workflow audit (2026-11-07)

**Input:** `PowerPath_Cofounder_GitHub_Handoff_2026-11-07.zip` (application v30.8.1 + Nov 1/Nov 3 patches).
**Output:** v30.8.2-audit — the same application with the fixes below. Protected financial engines are byte-identical (12/12 hashes unchanged); no underwriting math was touched.
**Method:** fresh install on Linux (Python 3.12, Node 22.23.4), CI-equivalent checks, full extended regression gate, dependency vulnerability scan, static review of server/auth/upload paths, then a scripted browser walkthrough (Playwright + axe-core) of every surface at desktop 1440, tablet 820 and mobile 390, plus end-to-end drives of each real workflow. Every fix was re-verified the same way.

## Findings and fixes

Severity: **P0** blocks a core workflow or corrupts data · **P1** serious defect or a clear barrier · **P2** polish or maintainability.

### Data integrity

| # | Sev | Finding | Fix |
|---|---|---|---|
| D1 | **P0** | **Saving a new scenario silently downgraded it to the legacy v25.8.5 engine.** The detailed workspace kept its own copy of the config, without the `engineVersion` the server assigns, and wrote that copy back on the first "Save version" / "Save & run". Every scenario a user created and then saved once ran on the old engine, and the financial bridge then rejected it. | Client now keeps the server's config. Server `PUT /scenarios/{id}` keeps the stored engine when an update leaves the field out; switching engines still requires naming one explicitly. Regression test added. **Check existing databases:** an underwriting scenario created after v27.1 that has version ≥ 2 and no `engineVersion` was probably downgraded by this bug. Scenarios from before v27.1 lack the field legitimately, so check the creation date before re-stamping. |

### Workflow dead ends (UX, the largest area)

| # | Sev | Finding | Fix |
|---|---|---|---|
| W1 | **P0** | **A project created in the main workspace could never reach any financial step.** It has no underwriting scenario, so Decision Center sensitivity, Power deliverability compare and Finance all showed an empty dropdown, a disabled button and no explanation. | Each dead end now explains why and links to the fix. Decision Center shows "Create underwriting scenario". Power deliverability shows a notice that deep-links to `/advanced?…&view=model&action=new-scenario`, which opens the form directly. |
| W2 | **P0** | **The financial compare failed with a raw engine message** ("Underwriting building IT MW must exactly equal feasibility target IT MW") when the scenario's buildings didn't add up to the project's MW. That is always the case for a new scenario, because defaults are 3 × 50 MW and PowerPath deliberately never assigns MW for you. | The page checks the totals before the user clicks and says exactly what's wrong ("models 150 MW … this project targets 200 MW"), with a link to edit the buildings. Server errors map to the same message. Verified end to end: create → edit to 200 MW → compare returns both paths. |
| W3 | **P0** | **Transaction review was unusable in practice.** For any project without registered inputs, "Load review" returned a 409 and showed a developer instruction to POST to an API endpoint. The review and debt schedule never appeared. | A one-click "Register public-filing inputs for this project" action with plain-language consent text. It then loads the review automatically. Verified: 24 facts, scenarios and the debt schedule render. |
| W4 | P1 | Agent operations showed an email/password sign-in form in local mode, where it can't work. Cause: CSS `.inline{display:flex}` overrode the `hidden` attribute. | Global `[hidden]{display:none!important}` in every stylesheet (test-enforced). |
| W5 | P1 | Transaction review showed "Sign out" when nobody had signed in. Clicking it revealed a sign-in form that local mode can't use. | Hidden in local mode. |
| W6 | P1 | Saving the agent schedule and queueing a review gave no feedback. | Explicit confirmations that also say jobs run only while a worker is started. Errors are styled. |
| W7 | P1 | PermitIQ: typing coordinates didn't resolve the state or county. Only a map click did, so the county list stayed empty for keyboard users. | Valid typed coordinates now trigger the same lookup as a map click. |
| W8 | P1 | Compare, Diligence and the Decision memo identified parcels by internal hash (`37183:nc-onemap-37183:2a0697df…`), while the list used the county PIN. | Readable "Parcel <PIN>" everywhere. The hash moves to a tooltip, and the memo keeps it in small print for traceability. |
| W9 | P2 | Creating a project gave no confirmation. | Toast plus guidance to confirm the brief. |

### Technical and engineering hygiene

| # | Sev | Finding | Fix |
|---|---|---|---|
| T1 | **P1** | `run_local.sh` was not executable in the archive, so the README's first command (`./run_local.sh`) fails on a fresh clone. | Executable bit set. CI asserts it. |
| T2 | **P1** | **Source drift:** the shipped `web/public/app.js` contained a hand edit (the "National screening ↗" link) missing from `web/src/app.ts`. The next TypeScript build would silently have deleted it. | Ported into the source. New `npm run check:ts-drift` (in CI) fails whenever the compiled output ≠ a fresh compile, and was proven to catch the original drift. `npm run build:ts` is pinned to TypeScript 5.6.3. |
| T3 | P1 | `npm run check` skipped 3 of 9 JS entrypoints (`geo.js`, `permitiq-national.js`, `parcel-footprint.js`). | All 9 covered (test-enforced). |

### Security review: no defects found

TrustedHost limited to loopback names (DNS-rebinding defence), cross-origin writes refused in middleware, strict CSP and anti-framing headers, upload extension whitelist with a 5 MB cap and exclusive-create writes, immutable evidence records, project-scoped download lookups, and parameterized SQL throughout the reviewed handlers (the one f-string, `_link_exists`, only interpolates hard-coded table names). pip-audit reports no known vulnerabilities. The handoff's own caveats still stand: local mode has **no authentication by design**, and the Postgres `set_config` actor model must stay server-side.

## Open items (not changed: they need a decision or are out of scope)

1. **The handoff P0s are unchanged:** PostgreSQL end-to-end parity, append-only protection for financial evidence (analyst role can hard-delete runs), RLS attack tests, and reconciling live schema with source. This audit ran on SQLite only.
2. **Wording that may overclaim:** financial compare rows label synthetic paths "Verified viable", which sits awkwardly with "not verified" everywhere else. The label comes from engine output, so it's a product call; it was not edited here.
3. **Three visual systems remain** (main workspace, detailed workspace, the navy transaction page). They are now linked and accessible but not unified. Recommend consolidating onto one shell before external pilots.
4. **The Transaction workspace is hard-wired to one real public company's filings** (Core Scientific). Confirm that framing is intended for anything shown outside the team.
5. **Maintainability:** 111 source lines exceed 400 characters (compressed one-liners in `workspace28.js`, `power-deliverability.js`, the server modules). Recommend running a formatter in a dedicated no-logic-change PR.
6. **Native `prompt()` / `confirm()`** are still used for agent review decisions and live-mode consent. Replace them with in-page dialogs.
7. **Diligence factor scoring** lives in the parcel inspector (step 2), not the Diligence step, which is a discoverability gap.
8. **Synthetic fixture parcels are named "def" and "abc".** Rename them to something clearly illustrative.
9. **Back-button navigation** between detailed-workspace views (URL now syncs via replaceState; full history support is a follow-up).
10. **Interpreter:** verified on Python 3.12.3. CI pins 3.12.10; confirm on the first CI run and on the Mac runtime.
